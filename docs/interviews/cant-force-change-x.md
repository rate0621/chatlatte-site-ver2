# X投稿（本文）

『嫌われる勇気』にこんな一節があります。「馬を水辺に連れていくことはできるが、水を呑ませることはできない」。

これを読んで、昔の失敗をひとつ思い出しました。

昔サーバー運用の仕事をしていて、手作業だったサーバー構築を「自動化しよう」というプロジェクトが始まったんです。私はエンジニアだったので仕組みを作りました。ところが現場に渡してみると「ここがちょっと」「これはどうなの」とあれこれ言われて、結局定着しなかった。

よく聞いてみたら、みんなそこまで自動化を求めてなかったんですよね。「自動化できるのはすごいね、嬉しいね」とは言う。でも本音は「別に、手作業がそんなに苦になってるわけじゃないし」だった。

どれだけすごいものを作っても、相手が求めてなければ使われない。これを実感した出来事でした。

（正直に言うと、あれは上からの「やれ」で始まったプロジェクトなので、事前に確かめたところで作らない選択肢はなかったんですけどね）

この経験で、仕事のやり方が変わりました。今は何かを作る前に、必ず「その業務でみんなが本当に困っているか」を確かめます。

「こう自動化できます、すごいでしょう」と見せると、たいてい「すごいね」とは言ってくれる。でもその「すごいね」は「困っている」とイコールじゃない。すごいと思っても、実は困ってないことが普通にあるんです。

作る側は「これだけすごいものを作ってるんだから喜ばれるはず」と思いがち。その気持ちをぐっと我慢して、作る前に「そもそも困ってますか?」と聞く。地味だけど、いちばん大事なことだと思っています。

続きはブログに書きました。
